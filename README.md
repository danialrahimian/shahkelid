# شاه‌کلید

**فروشگاه و پنل فروش اشتراک VPN، روی پنل [PasarGuard](https://github.com/PasarGuard/panel).**

مشتری پلن را انتخاب می‌کند، پول را می‌پردازد و چند ثانیه بعد لینک اشتراک و QR کدش را می‌گیرد. شما از بخش مدیریت فروش، مشتری‌ها، تیکت‌ها و گزارش‌ها را می‌گردانید. همه‌چیز روی یک سرور و با یک دستور نصب می‌شود.

- فارسی و راست‌به‌چپ، با تقویم شمسی (انگلیسی هم دارد)
- پرداخت با زرین‌پال، کارت‌به‌کارت، تتر (TRC20) و NOWPayments
- ساخت و تمدید خودکار اشتراک روی پنل PasarGuard
- پشتیبان‌گیری رمزگذاری‌شده‌ی خودکار: روی سرور، S3 و تلگرام
- نصب با یک دستور و سه سؤال؛ بقیه‌ی تنظیمات داخل پنل

## امکانات

### برای مشتری

- **خرید در چند ثانیه:** انتخاب پلن، پرداخت و تحویل فوری لینک اشتراک و QR کد.
- **روش‌های پرداخت:**
  - زرین‌پال
  - کارت‌به‌کارت با بارگذاری رسید
  - تتر روی شبکه‌ی ترون (TRC20): برای هر سفارش یک مبلغ دقیق اعلام می‌شود و پرداخت خودکار تشخیص داده می‌شود.
  - NOWPayments برای ارزهای دیگر
- **پنل مشتری:**
  - سرویس‌ها با حجم و روزهای باقی‌مانده، و تمدید با یک کلیک
  - سفارش‌ها و فاکتورها
  - تیکت پشتیبانی با پیوست تصویر
  - ورود دومرحله‌ای، و حذف حساب
- **یادآوری‌های ایمیلی:** ۳ روز و ۱ روز مانده به پایان، و در ۸۰٪ و ۱۰۰٪ حجم.
- **ورود بدون رمز** با کد ایمیلی؛ یا با رمز، برای کسی که رمز گذاشته.
- **بلاگ** با لایک، و نظرهایی که بعد از تأیید کارمند نمایش داده می‌شوند.

### برای شما و کارمندها

- **نقش‌ها و دسترسی‌ها:** مالک، مدیر، حسابدار، پشتیبان و نویسنده. هر کس فقط صفحه‌هایی را می‌بیند که اجازه دارد.
- **پنل‌ها، سرورها و پلن‌ها:** وصل کردن یک یا چند پنل PasarGuard، تعریف لوکیشن و سرور، و پلن‌هایی با حجم، مدت، تعداد دستگاه و قیمت.
  - زمان پلن از اولین اتصال مشتری شروع می‌شود.
  - مصرف هر ۵ دقیقه از پنل خوانده می‌شود.
- **مشتری‌ها (CRM):**
  - مرحله‌ی هر مشتری: سرنخ، فعال، در خطر ریزش، ریزش‌کرده، VIP
  - برچسب، یادداشت، سابقه‌ی سفارش‌ها و ایمیل‌های فرستاده‌شده
- **بررسی پرداخت‌ها:** رسیدهای کارت‌به‌کارت در صف بررسی می‌مانند. رسیدهای مشکوک علامت می‌خورند: تصویر یا شماره‌ی پیگیری تکراری، یا مبلغ متفاوت.
- **تیکت‌ها:** صف پشتیبانی به ترتیب فوریت و زمان انتظار، با یادداشت داخلی و دسته‌بندی.
- **گزارش فروش:**
  - درآمد، سفارش‌ها، میانگین خرید، نرخ تکمیل و تمدید
  - روزانه، هفتگی یا ماهانه‌ی شمسی، بر اساس پلن و روش پرداخت
- **قالب ایمیل‌ها:** متن هر ایمیل را بازنویسی کنید، پیش‌نمایش ببینید، یا خاموشش کنید.
- **گزارش فعالیت:** هر تغییری که کارمندها یا سیستم انجام داده‌اند، با نام انجام‌دهنده. این گزارش پاک‌شدنی نیست.
- **هشدار به مدیرها** با ایمیل و تلگرام:
  - پنل در دسترس نیست
  - ساخت اشتراک شکست خورده
  - پشتیبان‌گیری انجام نشده

### پشت صحنه

- **هیچ پرداختی گم نمی‌شود.** اگر پنل یا Redis موقتاً قطع باشد، کار در صف می‌ماند و بعد انجام می‌شود (الگوی outbox).
  - پرداخت زرین‌پالی که خریدار بعد از آن به سایت برنگشته، خودکار پیگیری می‌شود.
  - حساب‌ها با دفتر دوطرفه ثبت می‌شوند.
- **سریع:** با ۱۰٬۰۰۰ مشتری و بیش از ۴۴ هزار درخواست، هیچ خطایی رخ نداد و ۹۵٪ پاسخ‌های API زیر ۴ میلی‌ثانیه بودند.
- **دامنه‌ی پشتیبان:** اگر دامنه‌ی اصلی مسدود شد، سایت و لینک‌های اشتراک روی دامنه‌ی دیگری هم کار می‌کنند.
- **HTTPS خودکار** با Caddy و Let's Encrypt، پشت Cloudflare یا بدون آن.

## پیش‌نیازها

| چه چیزی | توضیح |
|---|---|
| **سرور مجازی خارج از ایران** | Ubuntu 24.04 یا 26.04. حداقل ۲ هسته، ۲ گیگ رم (۴ گیگ بهتر) و ۲۰ گیگ دیسک. |
| **دامنه** | رکورد `A` دامنه (و اگر می‌خواهید، `www`) به IP سرور |

این‌ها بعد از نصب، در پنل لازم می‌شوند:

| چه چیزی | توضیح |
|---|---|
| **سرویس ایمیل (SMTP)** | مثل Brevo، Mailgun یا Amazon SES. کد ورود مشتری‌ها با ایمیل می‌رود. |
| **مرچنت کد زرین‌پال** | از پنل زرین‌پال |
| **پنل PasarGuard** | جایی که اشتراک‌ها ساخته می‌شوند. می‌تواند روی سرور دیگری باشد. |
| اختیاری | ربات تلگرام برای هشدارها و پشتیبان‌ها، فضای S3، آدرس کیف پول تتر |

## نصب

روی سرور، با دسترسی root، این یک دستور:

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/danialrahimian/shahkelid/main/scripts/shahkelid.sh)" @ install
```

فقط سه چیز می‌پرسد:
1. دامنه
2. نام کاربری مالک
3. رمز مالک

پیام‌های نصب‌کننده و دستور `shahkelid` در ترمینال انگلیسی‌اند (ترمینال سرور فارسی را برعکس نشان می‌دهد).

خودش تشخیص می‌دهد:
- آیا دامنه به همین سرور اشاره می‌کند (و اگر نه، می‌گوید چه کنید)
- آیا `www` هم به سرور می‌آید
- آیا دامنه پشت Cloudflare است

بعد حدود ۱۰ دقیقه بدون سؤال کار می‌کند:
1. به‌روزرسانی سیستم، و swap اگر رم کم باشد
2. دیوار آتش. پورت SSH شما را خودش پیدا می‌کند تا دسترسی‌تان قطع نشود.
3. نصب Docker
4. ساختن رمزهای داخلی و راه‌اندازی
5. حساب مالک
6. نصب دستور `shahkelid` روی سرور
7. بررسی HTTPS

در پایان یک **رمز پشتیبان‌ها** نشان می‌دهد که باید **بیرون از سرور** نگه دارید. همین در `/root/shahkelid-install.txt` هم ذخیره می‌شود و هرگز در گزارش نصب نوشته نمی‌شود.

بعد از نصب:
1. `https://دامنه‌ی-شما/staff` را باز کنید و با نام کاربری و رمز وارد شوید. ورود دومرحله‌ای را با Google Authenticator یا 2FAS راه بیندازید.
2. در **تنظیمات فروشگاه** این‌ها را تنظیم کنید. هر کدام همان‌جا آزمایش می‌شود:
   - **ایمیل:** یک کد به ایمیلتان فرستاده می‌شود و باید آن را وارد کنید.
   - **تلگرام:** ربات بررسی می‌شود، گفتگوها خودشان پیدا می‌شوند و یک پیام آزمایشی می‌رود.
   - **درگاه‌های پرداخت:** زرین‌پال، تتر و NOWPayments.
   - **پشتیبان‌گیری:** روی سرور، و اختیاری S3 و تلگرام. با دکمه‌ی «همین حالا» آزمایش می‌شود.
3. پنل PasarGuard، سرورها، پلن‌ها و کارت‌های کارت‌به‌کارت را اضافه کنید و یک خرید آزمایشی انجام دهید.

جزئیات بیشتر، نصب آزمایشی بدون دامنه، نصب بدون سؤال و نصب دستی: [راهنمای نصب](docs/05-install.md)

## مدیریت با دستور `shahkelid`

| دستور | کار |
|---|---|
| `shahkelid status` | چه چیزی در حال اجراست و سالم است یا نه |
| `shahkelid logs app` | لاگ‌ها (یا `worker`، `web`، `backup`) |
| `shahkelid update` | نصب آخرین نسخه |
| `shahkelid backup` | یک پشتیبان همین حالا |
| `shahkelid backups` | فهرست پشتیبان‌ها |
| `shahkelid restore` | بازیابی: از سرور، از S3، یا از فایلی که ربات تلگرام فرستاده |
| `shahkelid owner password <نام کاربری>` | رمز تازه برای مالک |
| `shahkelid owner reset-2fa <نام کاربری>` | خاموش کردن ورود دومرحله‌ای مالکی که گوشی‌اش را گم کرده |
| `shahkelid domains add <دامنه>` | دامنه‌ی پشتیبان، برای وقتی دامنه‌ی اصلی مسدود شد |
| `shahkelid restart` / `down` / `up` | راه‌اندازی دوباره، توقف، روشن کردن |
| `shahkelid edit-env` | ویرایش تنظیمات سرور |
| `shahkelid uninstall` | حذف. پشتیبان‌های روی سرور می‌مانند. |
| `shahkelid help` | همه‌ی دستورها |

وقتی پنل، زرین‌پال، نوبیتکس یا ایمیل مشکل دارد چه کنید: [راهنمای عملیات](docs/06-operations.md)

## به‌روزرسانی

```bash
shahkelid update
```

کد تازه را می‌گیرد، برنامه را می‌سازد، تغییرات دیتابیس را اعمال می‌کند و همه‌ی سرویس‌ها را با نسخه‌ی تازه راه می‌اندازد. سایت چند ثانیه در دسترس نیست. خود دستور `shahkelid` هم همراه کد به‌روز می‌شود.

## پشتیبان‌گیری و بازیابی

- **چه چیزی:** دیتابیس، فایل‌ها (رسیدها، تصویرهای تیکت) و کلید رمزنگاری.
- **کجا:**
  - همیشه روی خود سرور
  - S3 (Backblaze B2، Cloudflare R2، …)، اگر در پنل روشن شده باشد
  - تلگرام، اگر روشن شده باشد: یک فایل رمزگذاری‌شده که ربات هشدارها می‌فرستد، مثل PasarGuard
- **هر چند وقت:** هر ۶ ساعت، یا هر فاصله‌ای که در پنل انتخاب شود.
- **امنیت و بررسی:** همه با **رمز پشتیبان‌ها** رمزگذاری می‌شوند ([restic](https://restic.net) و openssl). بعد از هر بار، بخشی از داده دوباره خوانده و بررسی می‌شود.
- **نگهداری:** از هر روز یک نسخه تا ۷ روز، از هر هفته تا ۴ هفته، و از هر ماه تا ۶ ماه.
- **خبر شکست:** اگر پشتیبان‌گیری شکست بخورد، به مدیرها ایمیل و پیام تلگرام می‌رود و در پنل هم دیده می‌شود.

**انتقال به سرور تازه:**
1. روی سرور تازه نصب کنید.
2. یکی از این دو را اجرا کنید:
   - `shahkelid restore <فایل‌ِ‌تلگرام>.skb`
   - `shahkelid restore latest --s3`
3. رمز پشتیبان‌های سرور قبلی را بدهید.

همه‌چیز برمی‌گردد، حتی تنظیمات پنل و ورود دومرحله‌ای کارمندها با همان برنامه‌ی Authenticator. کلید رمزنگاری داخل خود پشتیبان است، پس **فقط همان یک رمز لازم است**. این مسیر روی دو سرور شبیه‌سازی‌شده آزموده شده است.

## امنیت

- **ورود دومرحله‌ای کارمندها:** برای همه‌ی کارمندها اجباری است، از جمله مالکی که با نام کاربری وارد می‌شود.
- **محدودیت تعداد درخواست:** روی ورود و پرداخت. نشانی واقعی بازدیدکننده پشت Cloudflare هم درست دیده می‌شود.
- **حفاظت از داده‌ها:**
  - رمز پنل‌ها، ورود دومرحله‌ای و تنظیمات پنل (رمز SMTP، توکن تلگرام، کلیدها) در دیتابیس رمزگذاری‌شده نگه داشته می‌شوند. این رمزها بعد از ذخیره، دیگر نشان داده نمی‌شوند.
  - سرور هرگز کلید کیف پول نمی‌خواهد و نگه نمی‌دارد.
  - دیتابیس و Redis به اینترنت راه ندارند.
- **فایل‌های خصوصی:** رسیدها و پیوست‌ها هرگز عمومی سرو نمی‌شوند.

## توسعه

به **Node.js 24** و **Docker** نیاز دارید.

```bash
npm install                      # همه‌ی بسته‌ها، از ریشه
npm run services:up              # PostgreSQL 18 و Redis 7
npm run db:migrate -w back-end   # ساختن جدول‌ها
```

`back-end/.env.example` را به `back-end/.env` و `front-end/.env.example` را به `front-end/.env` کپی کنید. هر کدام در یک ترمینال:

```bash
npm run dev -w back-end          # API روی :5000
npm run dev:worker -w back-end   # worker: صف‌ها و کارهای زمان‌بندی‌شده
npm run dev -w front-end         # سایت روی :5173
```

بررسی کامل (lint، typecheck و همه‌ی آزمایش‌ها):

```bash
npm run check
```

جزئیات بیشتر در [راهنمای توسعه](docs/development.md).

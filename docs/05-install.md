# راهنمای نصب شاه‌کلید روی سرور

نصب شاه‌کلید با یک دستور انجام می‌شود و فقط سه چیز می‌پرسد: **دامنه**، و **نام کاربری** و **رمز** مالک فروشگاه. بقیه‌ی تنظیمات بعد از نصب، از داخل پنل مدیریت انجام و همان‌جا آزمایش می‌شوند:
- ایمیل
- تلگرام
- درگاه‌های پرداخت
- پشتیبان‌گیری

کل کار حدود ۱۵ دقیقه طول می‌کشد که بیشترش ساختن برنامه در اولین اجراست.

---

## پیش از شروع

| چه چیزی | توضیح |
|---|---|
| **یک سرور (VPS) خارج از ایران** | Ubuntu 24.04 یا 26.04، حداقل ۲ هسته، ۲ گیگ رم (۴ گیگ بهتر) و ۲۰ گیگ دیسک. |
| **یک دامنه** | در تنظیمات DNS دامنه، یک رکورد `A` به IP سرور بسازید (و اگر می‌خواهید، یکی هم برای `www`). |

بقیه را بعداً در پنل لازم دارید و لازم نیست همین حالا آماده باشند:
- یک سرویس ایمیل (SMTP) مثل Brevo یا Mailgun
- مرچنت کد زرین‌پال
- پنل PasarGuard
- اختیاری: ربات تلگرام، و فضای S3 برای پشتیبان‌ها

> در این راهنما `shop.example.com` یعنی دامنه‌ی شما و `203.0.113.10` یعنی IP سرور شما.

---

## نصب

به سرور وصل شوید و این دستور را اجرا کنید:

```bash
ssh root@203.0.113.10
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/danialrahimian/shahkelid/main/scripts/shahkelid.sh)" @ install
```

نصب‌کننده این‌ها را می‌پرسد (پیام‌های نصب‌کننده و دستور `shahkelid` انگلیسی‌اند، چون ترمینال سرور متن فارسی را به‌هم‌ریخته نشان می‌دهد):
1. **دامنه:** مثل `shop.example.com`.
2. **نام کاربری مالک:** حروف کوچک انگلیسی، عدد، `.` `-` `_`.
3. **رمز مالک:** دو بار. هنگام تایپ دیده نمی‌شود.

بعد خودش بررسی می‌کند که دامنه به همین سرور اشاره کند:
- اگر نکند، می‌گوید چه چیزی را درست کنید و دوباره بررسی می‌کند.
- اگر `www` هم به سرور اشاره کند، خودش آن را اضافه می‌کند.
- اگر دامنه پشت Cloudflare باشد، خودش تشخیص می‌دهد و تنظیمش را انجام می‌دهد.

### کارهایی که خودش انجام می‌دهد

بعد از تأیید شما، حدود ۱۰ دقیقه بدون سؤال کار می‌کند:
1. سیستم را به‌روز می‌کند. اگر رم کم باشد، swap می‌سازد.
2. دیوار آتش را روشن می‌کند: فقط SSH، ۸۰ و ۴۴۳ باز می‌ماند. پورت SSH فعلی را خودش پیدا می‌کند تا دسترسی شما قطع نشود.
3. Docker را نصب می‌کند.
4. کد را در `/opt/shahkelid` می‌گذارد و همه‌ی رمزهای داخلی را خودش می‌سازد.
5. برنامه را می‌سازد و راه می‌اندازد.
6. حساب مالک را می‌سازد.
7. دستور `shahkelid` را روی سرور نصب می‌کند.
8. بررسی می‌کند که سایت با HTTPS معتبر باز شود.

### رمز پشتیبان‌ها

در پایان یک **رمز پشتیبان‌ها** نشان می‌دهد. **همین حالا آن را جایی بیرون از سرور ذخیره کنید** (مثلاً در یک مدیر رمز). این رمز در `/root/shahkelid-install.txt` هم ذخیره می‌شود و فقط root می‌تواند آن را بخواند.
- همه‌ی پشتیبان‌ها با همین رمز رمزگذاری می‌شوند: روی سرور، در S3 و در تلگرام.
- با همین یک رمز، هر پشتیبان روی هر سرور تازه کامل برمی‌گردد، حتی ورود دومرحله‌ای کارمندان.
- بدون آن، هیچ‌کس، حتی خود شما، نمی‌تواند پشتیبان‌ها را بخواند.

## بعد از نصب

### ۱. ورود

1. `https://shop.example.com/staff` را باز کنید.
2. با نام کاربری و رمزی که دادید وارد شوید.
3. از شما خواسته می‌شود ورود دومرحله‌ای را با Google Authenticator یا 2FAS راه بیندازید. ده کد پشتیبانی که نشان داده می‌شود را هم ذخیره کنید.

### ۲. تنظیمات فروشگاه

به **تنظیمات فروشگاه** (`/staff/settings`) بروید. تا وقتی ایمیل تنظیم نشده، بالای همه‌ی صفحه‌های مدیریت یادآوری دیده می‌شود.

| بخش | چه کار کنید | آزمایش |
|---|---|---|
| **ایمیل (SMTP)** | مشخصات سرویس ایمیل را وارد و ذخیره کنید. | «ارسال کد آزمایشی» یک کد ۶ رقمی به ایمیلتان می‌فرستد. وقتی همان کد را وارد کنید، معلوم می‌شود ایمیل‌ها واقعاً می‌رسند. اگر سرویس ایمیل نپذیرد، پاسخ خودش نشان داده می‌شود (مثلاً `535 Authentication failed`). |
| **تلگرام** | توکن ربات را از ‎@BotFather بگیرید و ذخیره کنید. از تلگرام به ربات پیام بدهید و «پیدا کردن گفتگوها» را بزنید. | «بررسی ربات» نام ربات را نشان می‌دهد. «ارسال پیام آزمایشی» به هر گفتگو یک پیام می‌فرستد. آزمایش‌ها از خود سرور انجام می‌شوند، پس فیلتر بودن تلگرام در ایران اثری ندارد. |
| **درگاه‌های پرداخت** | مرچنت کد زرین‌پال؛ اختیاری: آدرس تتر (TRC20) و کلیدهای NOWPayments. | قالب هر کدام بررسی می‌شود. **برای تتر فقط آدرس دریافت را وارد کنید، هرگز کلید خصوصی را.** |
| **پشتیبان‌گیری** | هر چند ساعت یک بار. اختیاری: فرستادن به S3 یا به تلگرام، یا هر دو. | «بررسی دسترسی» برای S3، و «پشتیبان‌گیری همین حالا». نتیجه‌ی هر مقصد کنار آن نشان داده می‌شود. |

> تا ایمیل تنظیم نشود، مشتری‌ها نمی‌توانند با کد ایمیلی وارد شوند یا خرید کنند. صفحه‌ی ورود این را به آن‌ها می‌گوید.

### ۳. آماده کردن فروشگاه

در بخش مدیریت، به این ترتیب:
1. **پنل‌ها:** پنل PasarGuard را اضافه کنید. قبل از ذخیره بررسی می‌شود.
2. **سرورها و لوکیشن‌ها:** یک لوکیشن، بعد یک سرور روی آن پنل.
3. **پلن‌ها:** حجم، مدت، تعداد دستگاه و قیمت.
4. **پرداخت‌ها:** کارت‌هایی که برای کارت‌به‌کارت به خریدار نشان داده می‌شوند.

بعد یک خرید آزمایشی کامل انجام دهید:
- با یک ایمیل دیگر وارد شوید و ارزان‌ترین پلن را بخرید.
- ببینید لینک اشتراک ساخته می‌شود و در برنامه‌ی VPN کار می‌کند.

## مدیریت با دستور `shahkelid`

بعد از نصب، این دستور روی سرور هست:

| دستور | کار |
|---|---|
| `shahkelid status` | چه چیزی در حال اجراست و سالم است یا نه |
| `shahkelid logs app` | لاگ‌ها (یا `worker`، `web`، `backup`). خروج با `Ctrl+C` |
| `shahkelid update` | نصب آخرین نسخه: کد، برنامه و تغییرات دیتابیس |
| `shahkelid backup` | یک پشتیبان همین حالا، به همه‌ی مقصدهای تنظیم‌شده |
| `shahkelid backups` | پشتیبان‌های روی سرور (`shahkelid backups s3` برای S3) |
| `shahkelid restore` | بازیابی (بخش بعد) |
| `shahkelid owner password admin` | رمز تازه برای مالک، اگر فراموش شده |
| `shahkelid owner reset-2fa admin` | خاموش کردن ورود دومرحله‌ای مالکی که گوشی و کدهای پشتیبانش را گم کرده |
| `shahkelid owner create` | یک مالک دیگر |
| `shahkelid domains add backup-domain.net` | یک دامنه‌ی پشتیبان (بخش «دامنه‌ی پشتیبان») |
| `shahkelid restart` / `down` / `up` | راه‌اندازی دوباره، توقف، روشن کردن |
| `shahkelid edit-env` | ویرایش تنظیمات سرور (`.env`) |
| `shahkelid uninstall` | حذف. پشتیبان‌های روی سرور می‌مانند. |
| `shahkelid help` | همه‌ی دستورها |

جزئیات روزهای بد (پنل در دسترس نیست، زرین‌پال مشکل دارد، …): [راهنمای عملیات](06-operations.md)

## به‌روزرسانی

```bash
shahkelid update
```

این دستور به ترتیب:
1. کد تازه را می‌گیرد.
2. برنامه را می‌سازد.
3. تغییرات دیتابیس را اعمال می‌کند.
4. همه‌ی سرویس‌ها را با نسخه‌ی تازه راه می‌اندازد.

سایت چند ثانیه در دسترس نیست. خود دستور `shahkelid` هم همراه کد به‌روز می‌شود.

## پشتیبان‌گیری و بازیابی

هر پشتیبان این‌ها را دارد:
- دیتابیس
- فایل‌ها (رسیدها، تصویرهای تیکت)
- کلید رمزنگاری

پشتیبان به این مقصدها می‌رود:
- **همیشه روی خود سرور**، در `/var/lib/shahkelid/backups`
- **S3**، اگر در پنل روشن شده باشد
- **تلگرام**، اگر روشن شده باشد: یک فایل رمزگذاری‌شده‌ی `‎.skb` که ربات هشدارها می‌فرستد

### بازیابی روی همین سرور

```bash
shahkelid restore              # فهرست را نشان می‌دهد و می‌پرسد کدام
shahkelid restore latest       # آخرین پشتیبان روی سرور
shahkelid restore latest --s3  # آخرین پشتیبان در S3
```

### انتقال به سرور تازه

وقتی سرور قبلی از دست رفته یا عوض می‌شود:

1. روی سرور تازه، شاه‌کلید را با همان دستور نصب کنید. همان دامنه را بدهید؛ نام کاربری و رمز مهم نیستند، چون با بازیابی، حساب‌های قبلی برمی‌گردند.
2. یکی از این دو:
   - **فایلی که ربات تلگرام فرستاده:** آن را روی سرور بیاورید (مثلاً با `scp`) و اجرا کنید:
     ```bash
     shahkelid restore /root/shahkelid-20261019-1215.skb
     ```
   - **از S3:**
     ```bash
     shahkelid restore latest --s3
     ```
     نشانی bucket و کلیدهایش را می‌پرسد.
3. **رمز پشتیبان‌های سرور قبلی** را وارد کنید.
4. DNS دامنه را به IP سرور تازه بدهید.

همه‌چیز برمی‌گردد:
- حساب‌ها، سفارش‌ها و اشتراک‌ها
- تنظیمات پنل (ایمیل، تلگرام، درگاه‌ها)
- ورود دومرحله‌ای کارمندان، با همان برنامه‌ی Authenticator

> **هر چه بعد از زمان آن پشتیبان ثبت شده، از بین می‌رود.**

## دامنه‌ی پشتیبان

اگر دامنه‌ی اصلی مسدود شد، سایت و لینک‌های اشتراک روی دامنه‌ی دیگری هم کار می‌کنند:

1. رکورد `A` دامنه‌ی دوم را به همان IP بدهید.
2. اجرا کنید:
   ```bash
   shahkelid domains add backup-domain.net
   ```
3. در **پنل‌ها**، «دامنه‌ی لینک اشتراک» را روی دامنه‌ی تازه بگذارید تا لینک‌های تازه با آن ساخته شوند.

Caddy برای دامنه‌ی تازه خودش گواهی می‌گیرد. ورود و خرید هم روی آن کار می‌کند.

---

## پشت Cloudflare

نصب‌کننده خودش تشخیص می‌دهد که دامنه پشت Cloudflare است و نشانی‌های Cloudflare را مورد اعتماد می‌کند. بدون این کار، همه‌ی بازدیدکننده‌ها با IP خود Cloudflare دیده می‌شدند و محدودیت تعداد درخواست، همه را با هم حساب می‌کرد.

در Cloudflare:
- در SSL/TLS، حالت **Full (strict)** را انتخاب کنید.
- اگر گرفتن گواهی شکست خورد (`shahkelid logs web`)، «Always Use HTTPS» را موقتاً خاموش کنید، یا تا پایان نصب ابر را خاکستری (DNS only) کنید.

---

## نصب آزمایشی بدون دامنه

به‌جای دامنه، IP سرور را بدهید:
- Caddy گواهی را خودش امضا می‌کند و مرورگر هشدار «نامطمئن» می‌دهد.
- برای امتحان کافی است، **ولی برای فروش واقعی نه.**

---

## نصب بدون سؤال

برای خودکارسازی، همه‌چیز را در خود دستور بدهید. رمز از ورودی استاندارد خوانده می‌شود:

```bash
printf '%s\n' 'رمز-مالک' | sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/danialrahimian/shahkelid/main/scripts/shahkelid.sh)" @ install \
  --domain shop.example.com --username admin --password-stdin --yes
```

## اگر کار نکرد

| نشانه | کجا را ببینید |
|---|---|
| نصب وسط کار متوقف شد | گزارش کامل در `/var/log/shahkelid-install.log` است. بعد از رفع مشکل، همان دستور نصب را دوباره اجرا کنید. |
| صفحه باز نمی‌شود یا خطای گواهی می‌دهد | `shahkelid logs web`. معمولاً DNS هنوز به این سرور اشاره نمی‌کند، یا پورت ۸۰ در دیوار آتش سرویس‌دهنده بسته است (Let's Encrypt از آن استفاده می‌کند). |
| کد ورود به مشتری‌ها نمی‌رسد | **تنظیمات فروشگاه ← ایمیل**: کد آزمایشی بفرستید تا پاسخ سرویس ایمیل را ببینید. |
| یادآوری «آخرین پشتیبان‌گیری شکست خورد» | **تنظیمات فروشگاه ← پشتیبان‌گیری** نشان می‌دهد کدام مقصد شکست خورده؛ جزئیات: `shahkelid logs backup`. |
| رمز مالک فراموش شده | `shahkelid owner password <نام کاربری>` |
| وضعیت سرویس‌ها | `shahkelid status` |

## نصب دستی

برای وقتی که می‌خواهید هر قدم را خودتان ببینید (نصب‌کننده دقیقاً همین‌ها را انجام می‌دهد):

```bash
apt-get update && apt-get -y upgrade && apt-get install -y git curl openssl ufw
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw allow 443/udp && ufw --force enable
curl -fsSL https://get.docker.com | sh
git clone https://github.com/danialrahimian/shahkelid.git /opt/shahkelid
cd /opt/shahkelid/infra/production
./sk init                      # .env با همه‌ی رمزها؛ رمز پشتیبان‌ها را نگه دارید
nano .env                      # MAIN_DOMAIN=shop.example.com و SITE_ADDRESSES=shop.example.com, www.shop.example.com
./sk up
printf '%s\n' 'رمز-مالک' | ./sk owner create admin
ln -s /opt/shahkelid/scripts/shahkelid.sh /usr/local/bin/shahkelid
```

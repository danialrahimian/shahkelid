# راهنمای نصب شاه‌کلید روی سرور

این راهنما شاه‌کلید را از صفر روی یک سرور خالی نصب می‌کند. دو راه دارد:
- **نصب خودکار** با یک دستور (پیشنهادی): بخش «نصب خودکار» در پایین.
- **نصب دستی**، مرحله‌به‌مرحله: مراحل ۱ تا ۷. برای وقتی که می‌خواهید بدانید هر قدم چه می‌کند، یا نصب خودکار جایی گیر کرد.

کل کار حدود نیم ساعت طول می‌کشد که بیشترش ساختن ایمیج‌ها در اولین اجراست.

---

## ۰. پیش از شروع، این‌ها را آماده کنید

| چه چیزی | توضیح |
|---|---|
| **یک سرور (VPS) خارج از ایران** | Ubuntu 24.04 یا 26.04 LTS، حداقل ۲ هسته و ۴ گیگ رم و ۴۰ گیگ دیسک. با ۲ گیگ رم هم کار می‌کند، ولی ساختن ایمیج‌ها کند می‌شود. |
| **یک دامنه** | در تنظیمات DNS دامنه، یک رکورد `A` برای `example.com` و یکی برای `www.example.com` بسازید که به IP سرور اشاره کند. قبل از مرحله‌ی ۶ باید کار کنند: `ping example.com` باید IP سرور را نشان دهد. |
| **یک سرویس ارسال ایمیل (SMTP)** | کد ورود با ایمیل می‌رود، پس بدون آن کسی نمی‌تواند وارد شود. مثلاً Brevo، Mailgun یا Amazon SES. آدرس سرور، پورت، نام کاربری و رمز لازم است. دامنه‌ی فرستنده را در همان سرویس تأیید کنید (رکوردهای SPF و DKIM)، وگرنه ایمیل‌ها به Spam می‌روند. |
| **یک فضای ذخیره‌سازی سازگار با S3 برای پشتیبان‌ها** | مثلاً Backblaze B2 یا Cloudflare R2. یک bucket خالی بسازید و یک کلید دسترسی (Key ID و Secret) که فقط به همان bucket دسترسی داشته باشد. اگر هنوز ندارید، پشتیبان‌ها فعلاً روی خود سرور گرفته می‌شوند. ولی اگر سرور از دست برود، آن‌ها هم از دست می‌روند. |
| **مرچنت کد زرین‌پال** | از پنل زرین‌پال. |
| (اختیاری) **ربات تلگرام** | برای هشدارها به مدیرها: توکن ربات و شناسه‌ی چت‌ها. |

> **یک نکته درباره‌ی نمونه‌ها:** در همه‌ی این راهنما `example.com` یعنی دامنه‌ی خود شما و `203.0.113.10` یعنی IP سرور شما. هر جا دیدید، مقدار خودتان را بگذارید.

## نصب خودکار با یک دستور (پیشنهادی)

`install.sh` همه‌ی کارهای مراحل ۱ تا ۷ را خودش انجام می‌دهد. چیزهایی را که فقط شما می‌دانید می‌پرسد و هر جوابی را که بشود، همان لحظه بررسی می‌کند.

### اجرا

```bash
ssh root@203.0.113.10
git clone <نشانی مخزن کد شما> /opt/shah-kelid
bash /opt/shah-kelid/install.sh
```

اگر با کاربری غیر از root وارد شده‌اید، جلوی دو دستور آخر `sudo` بگذارید. اگر `git` روی سرور نیست، اول `apt-get install -y git` را اجرا کنید.

راه دیگر، بدون clone (اگر مخزن عمومی است):

```bash
curl -fsSL <نشانی خام فایل install.sh در مخزن> | sudo bash
```

در این حالت نشانی مخزن را هم می‌پرسد. برای مخزن خصوصی، نشانی را با توکن بدهید: `https://<توکن>@github.com/<کاربر>/<مخزن>.git`

### چه چیزهایی می‌پرسد

اول همه‌ی سؤال‌ها را یک‌جا می‌پرسد. تا وقتی خلاصه را تأیید نکنید، **هیچ چیزی روی سرور تغییر نمی‌کند**.

| سؤال | بررسی‌ای که همان لحظه انجام می‌شود |
|---|---|
| زبان (فارسی یا انگلیسی) | اگر ترمینال شما فارسی را درست نشان نمی‌دهد، انگلیسی را انتخاب کنید. |
| نصب تازه، یا انتقال از روی پشتیبان | |
| دامنه، `www`، دامنه‌های پشتیبان، Cloudflare | DNS هر نشانی بررسی می‌شود: باید به IP همین سرور اشاره کند. اگر نه، می‌گوید چه چیزی را درست کنید و دوباره بررسی می‌کند. |
| ایمیل مالک | |
| تنظیمات SMTP و فرستنده | یک کد ۶ رقمی به ایمیل مالک فرستاده می‌شود و باید آن را وارد کنید. این‌طوری معلوم می‌شود ایمیل‌ها واقعاً می‌رسند. |
| مرچنت کد زرین‌پال | قالبش بررسی می‌شود. |
| آدرس تتر (TRC20)، NOWPayments (اختیاری) | قالب آدرس بررسی می‌شود. **هرگز کلید خصوصی نمی‌خواهد.** |
| ربات تلگرام (اختیاری) | توکن از خود تلگرام پرسیده می‌شود. شناسه‌ی گفتگوها را خودش پیدا می‌کند (کافی است به ربات پیام بدهید) و یک پیام آزمایشی می‌فرستد. |
| پشتیبان‌ها: فضای S3، یا فعلاً روی همین سرور | بررسی می‌شود که فضای ابری در دسترس باشد. |
| نشانی پایش پشتیبان (اختیاری) | |

رمزها هنگام تایپ دیده نمی‌شوند و در گزارش نصب هم نوشته نمی‌شوند.

### بعد از تأیید، خودش انجام می‌دهد

حدود ۱۰ دقیقه، بدون سؤال دیگر:
1. سیستم را به‌روز می‌کند و ابزارها را نصب می‌کند. اگر رم کمتر از ۴ گیگ است، ۲ گیگ swap می‌سازد.
2. دیوار آتش را روشن می‌کند: فقط SSH، ۸۰ و ۴۴۳. پورت SSH فعلی را خودش پیدا می‌کند تا دسترسی شما قطع نشود.
3. Docker را نصب می‌کند.
4. فایل `.env` را با رمزهای تازه و جواب‌های شما می‌سازد.
5. `./sk up` را اجرا می‌کند.
6. حساب مالک را می‌سازد.
7. یک پشتیبان می‌گیرد و آن را می‌خواند، تا معلوم شود کلیدهای فضای ابری درست‌اند.
8. بررسی می‌کند که سایت با HTTPS معتبر جواب بدهد.

در پایان یک گزارش نشان می‌دهد و در `/root/shah-kelid-install.txt` هم ذخیره می‌کند (فقط root آن را می‌خواند). در این گزارش هست:
- نشانی سایت و نحوه‌ی ورود
- کارهای باقی‌مانده
- **دو رمزی که باید بیرون از سرور نگه دارید:** `RESTIC_PASSWORD` و `APP_ENCRYPTION_KEY` (توضیح در مرحله‌ی ۴)

بعد از آن از مرحله‌ی ۷ (ورود) و ۸ (آماده کردن فروشگاه) ادامه دهید.

### اگر وسط کار متوقف شد

- گزارش کامل در `/var/log/shah-kelid-install.log` است.
- بعد از رفع مشکل، همان دستور را دوباره اجرا کنید.
- اگر نصب کامل شده باشد، دوباره اجرا کردنش فقط **به‌روزرسانی** را پیشنهاد می‌دهد. تنظیمات و داده‌ها دست نمی‌خورند.

### انتقال به سرور تازه

روی سرور تازه همین اسکریپت را اجرا کنید و «انتقال از روی پشتیبان» را انتخاب کنید. این‌ها را می‌خواهد:
- همان bucket سرور قبلی
- دو رمزی که نگه داشته‌اید

خودش پشتیبان‌ها را نشان می‌دهد، آخری را برمی‌گرداند و یک پشتیبان تازه می‌گیرد. بعد فقط DNS را به IP سرور تازه بدهید.

### بدون سؤال (برای خودکارسازی)

هر سؤال اول یک متغیر را می‌خواند. اگر آن متغیر از قبل مقدار داشته باشد، سؤال پرسیده نمی‌شود. نام‌ها همان نام‌های `.env` هستند، به‌اضافه‌ی چند نام مخصوص نصب‌کننده (فهرست کامل در سر فایل `install.sh`). یک فایل جواب بسازید:

```bash
SK_LANG=fa
SK_MODE=new
SK_ADDRESS=domain
MAIN_DOMAIN=example.com
SK_WWW=y
SK_BACKUP_DOMAINS=
SK_CLOUDFLARE=n
SK_OWNER_EMAIL=you@example.com
SMTP_HOST=smtp-relay.brevo.com
SMTP_PORT=587
SMTP_USER=...
SMTP_PASSWORD='...'
MAIL_FROM='شاه‌کلید <no-reply@example.com>'
ZARINPAL_MERCHANT_ID=...
TRON_RECEIVE_ADDRESS=
NOWPAYMENTS_API_KEY=
TELEGRAM_BOT_TOKEN=
SK_BACKUP=s3
SK_S3_ENDPOINT=https://s3.us-west-004.backblazeb2.com
SK_S3_BUCKET=my-bucket
BACKUP_S3_ACCESS_KEY_ID=...
BACKUP_S3_SECRET_ACCESS_KEY='...'
BACKUP_PING_URL=
```

و اجرا کنید:

```bash
bash /opt/shah-kelid/install.sh --answers answers.env --yes
```

با `--yes`، اگر جواب لازمی کم باشد، به‌جای پرسیدن متوقف می‌شود. بعد از نصب، فایل جواب را پاک کنید: رمزها در آن است.

## ۱. وصل شدن به سرور و آماده کردن آن

از کامپیوتر خودتان:

```bash
ssh root@203.0.113.10
```

روی سرور، سیستم را به‌روز کنید و ابزارهای لازم را نصب کنید:

```bash
apt-get update && apt-get -y upgrade
apt-get install -y git curl openssl ufw
```

دیوار آتش: فقط SSH و وب باز باشند.

```bash
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw allow 443/udp
ufw --force enable
```

> دیتابیس و Redis هیچ پورتی روی سرور باز نمی‌کنند. فقط Caddy روی ۸۰ و ۴۴۳ است.

## ۴. ساختن فایل تنظیمات

```bash
./sk init
```

این دستور فایل `.env` را می‌سازد و همه‌ی رمزهایی را که خودش می‌تواند بسازد، پر می‌کند: رمز دیتابیس، رمز Redis، کلید نشست، کلید رمزنگاری و رمز پشتیبان‌ها.

> **مهم:** دو خطی که در انتها چاپ می‌کند (`RESTIC_PASSWORD` و `APP_ENCRYPTION_KEY`) را **همین حالا** جایی بیرون از این سرور ذخیره کنید، مثلاً در مدیر رمز عبورتان.
> - بدون `RESTIC_PASSWORD` هیچ‌کس، حتی خود شما، نمی‌تواند پشتیبان‌ها را بخواند.
> - بدون `APP_ENCRYPTION_KEY`، ورود دومرحله‌ای کارمندان و رمز پنل‌ها بعد از بازیابی کار نمی‌کند.

## ۵. پر کردن تنظیمات

```bash
nano .env
```

این‌ها را پر کنید. بقیه را همان‌طور که هست بگذارید.

| تنظیم | مثال | توضیح |
|---|---|---|
| `MAIN_DOMAIN` | `example.com` | دامنه‌ی اصلی، بدون `https://` |
| `SITE_ADDRESSES` | `example.com, www.example.com` | همه‌ی نشانی‌هایی که سایت روی آن‌ها باز می‌شود |
| `ALLOWED_ORIGINS` | *(خالی)* | خالی بگذارید. ورود و خرید از همه‌ی نشانی‌های `SITE_ADDRESSES` خودبه‌خود پذیرفته می‌شود. |
| `ACME_EMAIL` | `you@example.com` | برای اعلان‌های گواهی HTTPS |
| `SMTP_HOST`، `SMTP_PORT`، `SMTP_USER`، `SMTP_PASSWORD` | | از سرویس ایمیل |
| `MAIL_FROM` | `شاه‌کلید <no-reply@example.com>` | فرستنده‌ی ایمیل‌ها. دامنه‌اش باید در سرویس ایمیل تأیید شده باشد. |
| `ZARINPAL_MERCHANT_ID` | | مرچنت کد زرین‌پال |
| `TRON_RECEIVE_ADDRESS` | | اختیاری: آدرس کیف پول تتر روی ترون. **فقط آدرس، هرگز کلید خصوصی.** |
| `RESTIC_REPOSITORY` | `s3:https://s3.us-west-004.backblazeb2.com/my-bucket` | نشانی bucket، با `s3:` در ابتدا. اگر هنوز bucket ندارید: `/backups/restic`، یعنی روی خود سرور در پوشه‌ی `BACKUP_LOCAL_DIR` (پیش‌فرض `/var/backups/shah-kelid`). |
| `BACKUP_S3_ACCESS_KEY_ID`، `BACKUP_S3_SECRET_ACCESS_KEY` | | کلید دسترسی bucket |
| `TELEGRAM_BOT_TOKEN`، `TELEGRAM_ADMIN_CHAT_IDS` | | اختیاری، برای هشدارها |

با `Ctrl+O` و `Enter` ذخیره کنید و با `Ctrl+X` بیرون بیایید.

## ۶. راه‌اندازی

```bash
./sk up
```

بار اول ساختن ایمیج‌ها چند دقیقه طول می‌کشد. در پایان جدولی چاپ می‌شود که در آن `app`، `postgres`، `redis`، `backup` و `web` در حال اجرا هستند (`Up`) و بیشترشان `(healthy)`.

- `migrate` کارش را کرده و بسته شده (`Exited (0)`). این طبیعی است: ساختن جدول‌های دیتابیس فقط یک بار لازم است.
- `web` بار اول برای هر دامنه از Let's Encrypt گواهی HTTPS می‌گیرد. اگر DNS درست باشد، این کار چند ثانیه طول می‌کشد.

حالا `https://example.com` را در مرورگر باز کنید. صفحه‌ی اصلی شاه‌کلید باید با قفل سبز HTTPS دیده شود.

> اگر `./sk up` با خطا تمام شد یا صفحه باز نشد، بخش «اگر کار نکرد» در پایین را ببینید.

## ۷. ساختن حساب مالک و ورود

```bash
./sk create-owner you@example.com
```

1. در مرورگر به `https://example.com/account/sign-in` بروید.
2. همان ایمیل را بزنید و کدی را که به ایمیلتان می‌رسد وارد کنید.
3. از شما خواسته می‌شود ورود دومرحله‌ای را راه‌اندازی کنید (Google Authenticator یا 2FAS). ده کد پشتیبانی که نشان داده می‌شود را هم ذخیره کنید.
4. حالا `https://example.com/staff` بخش مدیریت است.

کارمندهای دیگر را از **تیم و نقش‌ها** در همان بخش اضافه کنید.

---

## ۸. آماده کردن فروشگاه

در `/staff` به این ترتیب:

1. **پنل‌ها:** پنل PasarGuard را اضافه کنید (نشانی و حساب پنل). قبل از ذخیره بررسی می‌شود.
2. **سرورها و لوکیشن‌ها:** یک لوکیشن، بعد یک سرور روی آن پنل.
3. **پلن‌ها:** حجم، مدت، تعداد دستگاه و قیمت.
4. **پرداخت‌ها:** کارت‌هایی که برای کارت‌به‌کارت به خریدار نشان داده می‌شوند.

بعد یک خرید آزمایشی کامل انجام دهید:
- با یک ایمیل دیگر وارد شوید و ارزان‌ترین پلن را بخرید.
- ببینید لینک اشتراک ساخته می‌شود و در برنامه‌ی VPN کار می‌کند.
- ایمیل «سرویس آماده است» هم باید برسد.

## ۹. بررسی پشتیبان‌ها

اولین پشتیبان همان لحظه‌ی راه‌اندازی گرفته شده است. ببینید هست:

```bash
./sk snapshots
```

باید دست‌کم یک ردیف نشان دهد. از این به بعد هر ۶ ساعت یک پشتیبان گرفته می‌شود:
- از هر روز یک نسخه تا ۷ روز، از هر هفته تا ۴ هفته، و از هر ماه تا ۶ ماه نگه داشته می‌شود.
- اگر پشتیبان‌گیری شکست بخورد، به مالک و مدیرها ایمیل (و اگر تنظیم شده، پیام تلگرام) می‌رود.

برای بازیابی، [راهنمای عملیات](06-operations.md) را ببینید.

## ۱۰. (اختیاری) دامنه‌ی پشتیبان

اگر دامنه‌ی اصلی مسدود شد، سایت و لینک‌های اشتراک می‌توانند روی دامنه‌ی دیگری هم باز شوند.

1. رکورد `A` دامنه‌ی دوم را به همان IP بدهید.
2. در `.env`:
   ```
   SITE_ADDRESSES=example.com, www.example.com, backup-domain.net
   ```
3. `./sk up`

Caddy برای دامنه‌ی تازه خودش گواهی می‌گیرد. ورود و خرید هم روی آن کار می‌کند، چون اپلیکیشن همین فهرست را می‌خواند.

---

## ۱۱. (اختیاری) پشت Cloudflare

1. در Cloudflare، رکوردهای DNS را «Proxied» (ابر نارنجی) کنید.
2. در SSL/TLS، حالت **Full (strict)** را انتخاب کنید.
3. نشانی‌های Cloudflare را در `.env` بگذارید تا سایت نشانی واقعی بازدیدکننده را ببیند:
   ```bash
   sed -i "s|^TRUSTED_PROXIES=.*|TRUSTED_PROXIES=$(curl -s https://www.cloudflare.com/ips-v4 https://www.cloudflare.com/ips-v6 | tr '\n' ' ')|" .env
   ./sk up
   ```

> بدون این تنظیم، همه‌ی بازدیدکننده‌ها از نشانی Cloudflare دیده می‌شوند و محدودیت تعداد درخواست همه را با هم حساب می‌کند.

## به‌روزرسانی

وقتی نسخه‌ی تازه آمد:

```bash
cd /opt/shah-kelid/infra/production
./sk update
```

این دستور به ترتیب:
1. کد را می‌گیرد.
2. ایمیج‌ها را دوباره می‌سازد.
3. تغییرات دیتابیس را اعمال می‌کند.
4. سرویس‌ها را یکی‌یکی بالا می‌آورد.

در این مدت سایت چند ثانیه در دسترس نیست.

## اگر کار نکرد

| نشانه | کجا را ببینید |
|---|---|
| `./sk up` با خطای `.env` تمام می‌شود | همه‌ی موارد مرحله‌ی ۵ پر شده‌اند؟ در production، اپلیکیشن بدون `SMTP_*` و `ZARINPAL_MERCHANT_ID` بالا نمی‌آید و خطا دقیقاً می‌گوید کدام کم است: `./sk logs app` |
| صفحه باز نمی‌شود یا خطای گواهی می‌دهد | `./sk logs web`. معمولاً DNS هنوز به این سرور اشاره نمی‌کند (`ping example.com`)، یا پورت ۸۰ بسته است (Let's Encrypt از آن استفاده می‌کند). |
| کد ورود نمی‌رسد | `./sk logs worker`. خطای SMTP آن‌جا نوشته می‌شود. |
| `./sk snapshots` خالی است یا خطا می‌دهد | `./sk logs backup`. معمولاً نشانی bucket یا کلیدها اشتباه است. |
| وضعیت سرویس‌ها | `./sk status` |

## نصب آزمایشی بدون دامنه

برای امتحان کردن روی یک سرور یا ماشین مجازی بدون دامنه، در مرحله‌ی ۵:

```
MAIN_DOMAIN=localhost
SITE_ADDRESSES=localhost
CADDY_LOCAL_CERTS=local_certs
```

Caddy گواهی را خودش امضا می‌کند و مرورگر هشدار «نامطمئن» می‌دهد. برای امتحان کافی است، **ولی برای سرور واقعی نه**.
